# Своё Вино — сканер и результаты

Nuxt 3 / Vue 3. Главная страница и оформление сканера обновлены из [daitemnesil/svoe-vino-scanner](https://github.com/daitemnesil/svoe-vino-scanner), коммит `f430cfcb3a9142d9f4d357d30d6b098b196bd98a`. Сохранены новые отступы и фотографии `vine1.jpg` / `vine2.jpg`; поверх этой версии добавлены два сценария результата, связанные фильтры и подтверждение 18+.

## Запуск

```bash
npm ci
npm run dev
```

На Windows при ограничениях PowerShell используйте `npm.cmd`.
`npm run build` собирает статический фронтенд Nuxt в `.output/public`. Сервер статического сайта должен возвращать `index.html` для неизвестных маршрутов (SPA fallback). Для сборки с собственным сервером Nuxt можно использовать `npm exec nuxt build`.

## Страницы

- `/scan` — загрузка / камера и ссылки на оба примера результата.
- `/wine/cantiani-cabernet-sauvignon-reserve-2024?demo=1` — пример найденного вина.
- `/wine/:slug` — карточка любого из 2105 вин по slug из каталога.
- `/not-found?demo=1` — пример отсутствующего вина с подборкой красных сухих вин и приоритетом Каберне Совиньон.
- `/not-found` — подбор по известным характеристикам; без параметров приложение просит их выбрать и не выдумывает свойства этикетки.

## Каталог

`public/catalog/wines.json` импортирован из предоставленного `wines(1).xlsx`: все 2105 уникальных записей. Производитель, категория, регион, цвет, крепость, температура, виноград, описание, гастрономические сочетания, рейтинг, URL и изображения берутся из файла. Служебные поля похожих вин тоже сохранены. Числовые значения крепости Excel (например `0.14`) нормализованы в `14%`.

В исходной таблице нет отдельного поля года. Год берётся из названия только при наличии одного явного года; иначе показывается «Год не указан». Рейтинг — рейтинг из каталога, без утверждения, что это оценка Роскачества. Изображения загружаются с адресов из таблицы; если источник недоступен, показывается текстовое состояние.

Повторный импорт (Python + `openpyxl`):

```bash
python scripts/import_catalog.py path/to/wines.xlsx
```

Рекомендации: выбранные категория, виноград, регион и блюдо ограничивают подборку. Год, если он известен, влияет на порядок; при равенстве учитываются рейтинг и название. Параметры можно уточнить на странице. Без известных характеристик подбор не выполняется. Карусель поддерживает свайп, колёсико/трекпад, кнопки, клавиши ←/→ и Home/End. Каждая карточка показывает гастросочетания и ведёт на исходную страницу вина в «Своё Вино».

Списки характеристик зависят друг от друга: каждый показывает только варианты, совместимые со всеми остальными выбранными параметрами в локальном каталоге. Начинать можно с любого поля. Выбранное значение можно заменить или снять; «Сбросить параметры» возвращает полные списки. Если распознавание передало несовместимые характеристики, сохраняется доступное сочетание в порядке категория → сорт → регион → блюдо, а страница сообщает об изменении. Год не ограничивает эти списки, поскольку в исходных данных он указан не для всех вин.

При первом входе на любую страницу открывается окно 18+. До подтверждения содержимое недоступно для взаимодействия, окно не закрывается по Escape или нажатию на фон. При отказе появляется сообщение об ограничении доступа. Подтверждение хранится в `localStorage` только на этом устройстве 30 дней; при недоступном хранилище действует до перезагрузки. Это самостоятельное подтверждение возраста, а не проверка документов. В подвале всех страниц также есть метка 18+.

В карточке вина блок «С чем сочетать» расположен перед блоком «Характер вина» на всех устройствах.

Последняя карточка карусели — переход в полный каталог с выбранными фильтрами. Используются реальные ключи `colors`, `sweetness`, `grapes`, `regions`, `dishes` и значения из открытых справочников сайта (зафиксированы в `data/catalogFilters.json`). Например: `https://vino-svoe.ru/wines?colors=krasnoe&sweetness=suhoe&grapes=kaberne-sovinon&regions=kuban&dishes=meat`. Ссылка проверена по ответу каталога: 80 результатов. Внешний каталог не поддерживает фильтрацию по году; такие параметры явно отмечаются как требующие уточнения, вместо создания несуществующего URL-параметра. Скролл до конца сам по себе не уводит со страницы: переход выполняется по нажатию на последнюю карточку.

## Подключение распознавания

По умолчанию `NUXT_PUBLIC_USE_MOCK=true`: это явно обозначенная демонстрация интерфейса. Фото не анализируется; выбранный сценарий возвращает реальную запись каталога либо демонстрационный профиль. Выдуманных процентов уверенности нет.

Для реального сервиса установите `NUXT_PUBLIC_USE_MOCK=false` и при необходимости `NUXT_PUBLIC_API_BASE=https://your-api.example` перед сборкой. `POST /api/scan` принимает `multipart/form-data`, поле `image`. Бэкенд должен разрешить CORS для домена фронтенда при разных origin.

Найдено:
```json
{ "found": true, "wine": { "slug": "cantiani-cabernet-sauvignon-reserve-2024" } }
```

Не найдено / нет уверенного совпадения:
```json
{ "found": false, "profile": { "category": "Красное сухое", "grapes": ["Каберне Совиньон"], "region": "Кубань", "dish": "Мясо и стейки" } }
```

Передавайте только определённые характеристики; `profile` необязателен. Неизвестный slug переводит к подбору. Детальные сведения всегда разрешаются по локальному каталогу. Фото хранится в памяти вкладки на время перехода, после перезагрузки не сохраняется. Выбор нового результата освобождает предыдущий объект изображения.

Опубликованная версия Sites — статический фронтенд; сервис распознавания в этот проект не включён.
